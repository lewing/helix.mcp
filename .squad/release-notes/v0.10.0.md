# v0.10.0 — Helix job summaries, evidence planning, and snapshot CLI tooling

Minor release focusing on queue-monitor compatibility, deterministic evidence planning for failed jobs, and snapshot validation CLI. The `azdo_helix_jobs` tool now preserves complete Helix job summaries instead of reducing them to GUIDs; the new `azdo_evidence_plan` tool maps artifacts to failed jobs deterministically; and new snapshot export/validation commands enable pre-release validation workflows.

## Highlights

- **Queue-monitor-compatible Helix job discovery** (#132) — `azdo_helix_jobs` now preserves full job summaries including state, queue ID, work-item counts, and fallback timeline issues for jobs without canonical Helix metadata, enabling queue-monitor monitoring without a separate scrape.
- **Deterministic evidence planning** (#128) — New `azdo_evidence_plan` tool maps artifacts to failed or canceled jobs via GUID join (100% resolution on real builds) with normalized-name fallback; available as MCP tool and CLI.
- **Snapshot export and validation CLI tooling** (#125) — New `hlx snapshot export` and `hlx snapshot validate` commands enable exporting MCP tool output to JSON and replaying it against updated code without making live API calls.
- **Snapshot-backed evaluation mode** (#124) — New `--snapshot` mode for MCP tools allows evaluation workflows to use saved snapshots instead of live queries for deterministic testing and cost reduction.
- **Harden snapshot export correctness** (#127) — Snapshot export now correctly handles matrix filtering and validates serialization contracts before output.
- **Trailing-glob fix for evidence pattern matching** — `StringHelpers.MatchesPattern` now correctly resolves trailing-`*` prefix patterns, enabling `hlx azdo artifacts --pattern 'Logs_Build_*'` for evidence extraction.

## New Features

- **`azdo_helix_jobs` job summary preservation** (#132) — Helix job results now include optional state, queueId, workItemCount, superseded, taskErrorCount, taskWarningCount, and fallback timeline issues; strategy field identifies lookup path (`helix` or `timeline`); source field tracks the computed source ID used for the primary Helix query.
- **`azdo_evidence_plan` — artifact-to-job mapping tool** (#128) — New MCP and CLI tool for planning evidence artifacts corresponding to failed or canceled jobs; supports GUID join (primary, 100% resolution) and normalized-name matching (fallback); configurable matching strategy (`auto`, `source-id`, `normalized-exact`, `exact`); returns completeness signals, ranked candidates, and per-job mapping status.
- **Snapshot export and validation CLI** (#125) — `hlx snapshot export [TOOL] --output FILE` saves tool output to JSON for reproducible testing; `hlx snapshot validate [TOOL] --snapshot FILE` replays saved snapshots for comparison workflows.
- **Snapshot-backed evaluation mode** (#124) — MCP tools accept optional `--snapshot FILE` parameter to evaluate against saved snapshots instead of live queries; enables deterministic testing and cost-free re-evaluation of prior queries.
- **Active queue-monitor error surface** (#132) — `azdo_helix_jobs` result includes `timelineIssues` array surfacing active task errors and warnings from AzDO timeline alongside Helix job summaries.

## Bug Fixes

- **Trailing-glob pattern matching** (#130) — `StringHelpers.MatchesPattern` now correctly handles trailing-`*` patterns (e.g., `"Logs_Build_*"`); previously matched nothing because they were treated as literal substrings.
- **Snapshot export edge cases** (#127) — Fixed matrix filtering and serialization validation in snapshot export to ensure consistency with live tool invocations.
- **Queue-monitor error message truncation** (#132) — Fallback timeline issues are bounded to 20 entries of 500 characters each; omitted-count markers preserve diagnostic accuracy when truncation occurs.
