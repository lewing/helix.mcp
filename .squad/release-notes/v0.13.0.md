# v0.13.0 — Query-backed build sets and build-set collection

## Headline

A minor release that turns `azdo_builds` into a query-backed, pageable build-discovery surface and adds `hlx collect azdo-builds` to capture an entire build set into one replayable manifest and snapshot.

## Highlights

- **Query-backed build discovery** (#167) — `azdo_builds` / `hlx azdo builds` add pipeline name/glob resolution, build-number globs, tags, result/reason and repository filters, opt-in compact projection, capture-anchored paging, and verified file/output delivery for complete selections.
- **Build-set collection** (#167) — `hlx collect azdo-builds --query <file>` freezes discovery, collects each member's evidence (or metadata only), and writes one schema-v2 manifest plus one existing-format snapshot that replays offline for exact and provably covered-subset queries.
- **Large builds without numeric unlocks** (#167) — explicit `--test-scope all` streams every result through hash-verified cache pages beyond 10,000, and explicit `--test-attachment-scope all` no longer needs `--max-test-attachments`.
- **Exact recovery instead of guessed caps** (#167) — unattended thresholds checkpoint and return the exact original argv plus `--allow-large --resume` with a fresh export destination.
- **Windows publish race fixed** (#166) — artifact cache publication tolerates concurrent Windows readers without corrupting or rejecting verified evidence.

## Breaking changes

- **`hlx azdo builds --json` shape changed** (#167). JSON output is now an envelope with `.results[]`, `complete`/`truncated`/`total`/`next`, source/query/definition/cache metadata, `viewId`, and recovery actions rather than the bare build array. Update scripts from `.[]` to `.results[]`, or use `--raw-json` for the bare row array (`--all --projection full --raw-json` preserves the old full-array representation). `--schema` now describes the envelope.
- **Partial build pages fail closed** (#167). When more matching builds exist than the inline page (including the default top=20), `hlx azdo builds` exits `2` and prints a `Continue:`/`Recover:` action to stderr unless `--allow-truncated` is supplied. Use `--all`, `--output`, or `--delivery file|chunked` for the complete selection; fully delivered output exits 0.
- **Conflicting `top`/`limit` rejected** (#167). Supplying different explicit `top` and `limit` values to `azdo_builds` / `hlx azdo builds` is now an error.

## New Features

- **Build filters and projections** (#167) — definition names use exact equality unless `*`/`?` appears; duplicate exact names form a union. `--build-number`, `--tags` (AND semantics), `--result`, `--reason`, `--repository-id`, and `--repository-type` join the existing branch/PR/definition/status/time filters. `projection=full` (default) preserves provider fields; `projection=compact` returns IDs, number/status/result/reason, definition, branch/times, repository, and full `webUrl`.
- **Paging and delivery** (#167) — `offset`/`limit`/`viewId`/`next` paging uses capture-anchored view IDs that refuse shifted live membership. `--all`, `delivery=auto|inline|file|chunked`, and `--output` deliver complete selections as streamed output or verified evidence readable through `hlx_read_evidence`. MCP `maxResponseBytes` (default 12,288) shapes responses but never denies data. `total` is exact only after source exhaustion.
- **`hlx collect azdo-builds --query <file>`** (#167) — the strict version-1 query file holds semantic filters only (paging/output settings are rejected). `--build-scope evidence|metadata`, `--json` (compact report), and `--json-manifest` (full persisted manifest) are supported alongside all single-build retry/cache/export/resume/log/test/attachment/Helix/binary policy flags. Members run sequentially within the existing resource semaphore; provider failures are isolated per build.
- **Overridable collection-only limits** (#167) — `--max-builds` 50, `--max-definitions` 25, `--max-scan-builds` 5,000, `--max-set-test-results` 10,000, and `--max-set-test-attachments` 1,000 are unattended planning safeguards, not access gates; explicit larger values are honored. Deferrals save a discovery checkpoint and return exact next steps (original argv + `--allow-large --resume`, original cache/manifest paths, fresh export destination).
- **Offline build-set replay** (#167) — complete `builds:v2:<query-hash>:all` evidence replays credential-free at any limit/projection, and a collect manifest can prove a complete source covers a narrower query (result/status/reason, definition/repository/branch/PR/tags/time). `not_in_snapshot` errors include an exact live-mode recollection command.
- **Streamed test-result evidence** (#167) — all-outcome results stream in bounded, content-addressed, hash-verified pages with checkpoints; derived failed-result indexes are rebuilt from captured pages after eviction.

## Bug Fixes

- **Strict MCP `result` binding** (#167) — the new `azdo_builds` `result` filter and `azdo_timeline` `result` bind directly under strict tools/call binding and are not rewritten to `resultFilter`; that alias stays scoped to `azdo_search_timeline`, now with regression coverage for both tools.
- **Windows artifact-publish race** (#166) — publication retries file-replacement contention and accepts an already-published destination only when its length and SHA-256 match.
- **AzDO list continuation** (#167) — legitimate traversals beyond the legacy continuation page batch are returned instead of failing as `invalid_response`; repeated-token/URL/shape guards still catch provider corruption.
- **Build-set resume and recovery correctness** (#167) — resume rejects missing manifests before discovery, verifies capture identity and membership hashes, preserves checkpoints across newer browsing captures and after failed discovery retries, reuses cached Helix files, and returns `discovery_recapture_required` with an exact fresh-capture command when discovery evidence is missing or mismatched.
- **Budgets, exit codes, and isolation** (#167) — Helix bytes are charged once per member; completed AzDO transfer usage survives later failures; policy-only deferrals honor `--allow-incomplete`; discovery acquisition failures keep exit 2; hard-error details never persist unclassified exception text; only selected member IDs are retained between passes.
- **Streamed-page integrity** (#167) — checkpoints and backing pages are verified before reuse; expired/completed checkpoints restart at offset zero; missing/corrupt pages and provider failures surface as classified, replayable cache errors.

## Dependencies

- **zizmor-action 0.6.4 → 0.7.1** (#168) — SHA-pinned bump of the GitHub Actions security linter.
- No SDK or NuGet package-version changes.

## Infrastructure

- **Regression coverage** (#166, #167) — new build-set query, review-regression, strict-binding, paging-contract, volume-policy, and SQLite publish-concurrency tests.

## Known limitations

- Build-set members are collected sequentially; there is no nested per-member concurrency (#167).
- Plain exported caches support exact complete queries only; covered-subset replay requires a collect manifest, and a failed-only set cannot prove all results, another repository, or a different time field (#167).
- `--allow-large` waives logical thresholds only; it does not bypass auth, integrity, or real storage limits (#167).
