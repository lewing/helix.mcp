# v0.10.3 — Visible AzDO failures and CI guidance hardening

## Headline

Patch release making hidden Azure DevOps test failures visible, authentication problems explicit, and CI guidance clearer for merged CoreCLR runners.

## Highlights

- **Real AzDO failed-test counts** (#150) — `azdo_test_runs` now reports failed tests from the available Azure DevOps counters, including unanalyzed, incomplete, and not-applicable results.
- **Explicit AzDO auth and deletion failures** (#150) — Redirects, HTTP 203, HTML sign-in pages, and deleted test-result runs now surface actionable errors instead of misleading empty results.
- **Reliable large-result paging and cache freshness** (#150) — Test results and runs page past Azure DevOps caps, empty result lists are not cached, and versioned cache keys avoid stale pre-upgrade entries.
- **Clearer Build Analysis evidence guidance** (#145) — Build-analysis evidence and live monitor guidance now better describe available timeline, log, and Helix signals.
- **CI and Windows stability fixes** (#150) — CoreCLR merged-runner exit-code guidance and artifact-cache sharing retries address recent CI confusion and red Windows runs.

## New Features

- No new user-facing features; this is a bug-fix patch release.

## Bug Fixes

- **Hidden AzDO failures made visible** (#150) — `azdo_test_runs` derives failed-test totals from `unanalyzedTests` and related counters so failed tests no longer appear as zero.
- **AzDO authentication failures no longer look empty** (#150) — Authentication redirects, HTTP 203 responses, and HTML sign-in pages now raise auth errors instead of returning empty data.
- **Deleted test-result runs are explicit** (#150) — 404 responses while reading test-run results now report that the run may have been deleted.
- **Large AzDO result sets page correctly** (#150) — Test results and runs now continue paging beyond Azure DevOps' 10,000-item cap.
- **Stale empty test-result caches avoided** (#150) — Empty test-result lists are not cached, and AzDO test cache keys are versioned so older misleading entries are not served after upgrade.
- **Redirect handling fixed for MCP AzDO calls** (#150) — The MCP AzDO HTTP client no longer auto-follows redirects, preserving auth-error detection.
- **Windows artifact-cache sharing retry** (#150) — Artifact cache reads and writes retry transient Windows sharing violations to prevent spurious CI failures.

## Dependencies

- **GitHub Actions updates** (#143, #146, #147, #148) — Updated `zizmor-action` to 0.6.4, `docker/build-push-action` to 7.4.0, `docker/setup-buildx-action` to 4.4.1, and `docker/setup-qemu-action` to 4.4.0.

## Infrastructure

- **Build Analysis guidance clarified** (#145) — Documentation and tests now describe evidence availability and live monitor behavior more accurately.
- **CoreCLR merged-runner CI guidance** (#150) — CI guide notes that merged CoreCLR runners can exit 100 even when tests fail, helping investigators distinguish runner behavior from infrastructure errors.
