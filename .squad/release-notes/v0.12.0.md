# v0.12.0 — Bounded timeline triage and verified evidence bytes

## Headline

A minor release that puts actionable timeline failures first, keeps complete evidence reachable through cache-backed delivery, and adds verified AzDO artifact/member and test-attachment downloads.

## Highlights

- **Triage-first timelines** (#159) — `azdo_timeline` and `hlx azdo timeline` now default to a bounded, errors/Helix-first view with ancestor context, issue previews, selectors, and stable paging instead of an unbounded full-record response.
- **Complete evidence remains reachable** (#159, #161) — explicit file/chunked delivery and `hlx_read_evidence` / `hlx evidence read` expose verified evidence without squeezing full records or binary bytes into inline responses. Delivery files live under the hlx cache root, outside immutable eval snapshots.
- **AzDO artifact and attachment bytes** (#161) — new `hlx azdo download-artifacts` and `hlx azdo download-test-attachments` commands (and MCP equivalents) download whole archives, selected members, and original attachments with verified SHA-256 receipts.
- **Opt-in byte collection** (#161) — collector selectors, byte scopes/modes, and explicit budgets add selected bytes and provenance to replayable snapshots; metadata-only discovery does not imply unselected bytes were captured.
- **Reliable Helix uploaded-file downloads** (#164, fixes #162) — Vitek Karas's fix uses listed absolute blob URLs, eliminating broken relative redirects and misleading JSON errors across downloads, searches, test-result parsing, and collection.

## Breaking changes

- **Timeline defaults and JSON shape changed** (#159). MCP `azdo_timeline` now defaults to `projection=triage`: at most 10 rows, Phase rows omitted, and shortened issue previews. Use `projection=full` with paging or `delivery=file` for full detail. CLI `hlx azdo timeline --json` now returns an envelope with `.results[]`, completeness, paging, and view identity rather than the legacy `{id, records}` object. Update scripts from `.records[]` to `.results[]`, or use `--raw-json` to preserve the old shape.
- **Partial timeline pages fail closed** (#159). CLI output exits `2` when the selected view is incomplete unless `--allow-truncated` is supplied. Follow `next` or request the complete selection with `--all`, `--delivery file|chunked`, or `--output`; physically writing a partial selection does not make it logically complete.

## New Features

- **Timeline selectors and projections** (#159) — `recordId`, `parentId`, `type`, `result`, `state`, `name` globs, and `expand` narrow the view. Explicit selectors without a preset resolve `filter` to `all`, so exact lookups are not implicitly restricted to failures. `triage`, `compact`, `full`, and `summary` projections share `offset`/`limit`/`viewId`/`next` paging and reject stale view IDs. Triage includes up to five deduplicated issue previews per row, counts, log IDs, and ancestor context.
- **Access-first delivery** (#159) — `delivery=auto|inline|file|chunked` keeps large records and issue windows accessible as verified evidence references. The default inline target is 12,288 bytes, clamped to 8–16 KiB; responses report both requested and effective budgets. These are presentation targets, not data-access ceilings.
- **Artifact/member downloads** (#161) — `azdo_download_artifacts` / `hlx azdo download-artifacts` stream selected evidence to private cache-backed disk. Exact PipelineArtifact members use native `format=file&subPath=/relative/path` transfers; member globs use seekable disk spooling and selected extraction with CRC/SHA validation. Whole archives and original dump bytes remain explicitly available.
- **Test-attachment downloads** (#161) — `azdo_download_test_attachments` / `hlx azdo download-test-attachments` support filename/member selection and verified receipts. Omit `resultId` for additive run-level attachment listing; content labels and the ordinary cache target do not decide download eligibility.
- **Local evidence reads** (#161) — `hlx evidence read <evidence-id>` supports byte offsets, bounded UTF-8/base64 reads, and full `--output` delivery using the same verified evidence backing as `hlx_read_evidence`.
- **Opt-in collector bytes** (#161) — artifact-name/member and attachment filename/member selectors, `--artifact-byte-scope`, `--artifact-byte-mode`, `--allow-large`, and streamed-byte planning capture selected verified blob/descriptor pairs with source provenance. Required member selections with no matches remain explicit incomplete gaps.

## Bug Fixes

- **Helix uploaded-file URLs** (#164, fixes #162) — contributed by **Vitek Karas**. Downloads use absolute blob URLs from file listings and reuse resolved links/cached listings without bypassing the artifact-byte cache. Expired cached links refresh the listing and retry once on HTTP 401/403/404/410; successful downloads do not incur extra listing requests.
- **Timeline completeness and continuation correctness** (#159) — logical completeness comes from the projected selection rather than physical file delivery. Issue windows, malformed graphs, clipped previews, selector precedence, Helix-first ranking, and continuation settings retain accurate recovery paths.
- **Evidence isolation and integrity** (#159, #161) — evidence reads resolve the originating AzDO credential partition independently per request. Output guards resolve physical snapshot/ancestor paths, including symlink chains; copies verify staged length and SHA-256 before publication or overwrite.
- **Byte download integrity and recovery** (#161) — unsolicited partial HTTP bodies are never published as complete; length/SHA/CRC failures are classified per resource/member without discarding other successes. Cached members are checked against the current catalog, interrupted native transfers restart the current file, and verified completed files are reused. Original archives remain downloadable when `--all-members` expands report coverage.
- **Cache retention, budgets, and Windows portability** (#161) — byte paths are portably hashed; blob/descriptor pairs survive metadata TTL together and expire/evict together. Shared retained/streamed budgets preserve zero remaining capacity unless `--allow-large` is explicit. SQLite WAL writers use private page caches, with scoped pool cleanup after disposal.

## Dependencies

- No SDK, package-version, or security-pin changes in this release.

## Infrastructure

- **Cache-root evidence storage** (#159) — live evidence uses `<effective-cache-root>/delivery/<credential-partition>/`. Eval delivery uses `<normal-user-cache-root>/eval-delivery/<snapshot-hash>/<credential-partition>/` outside the snapshot, with an ephemeral fallback for overlapping roots. Delivery has a separate soft budget and 24-hour pins; with the ordinary cache disabled, delivery remains available under the base cache root's `delivery-ephemeral/` directory.
- **Regression coverage** (#159, #161, #164) — expanded timeline, paging, evidence-delivery, byte-integrity, offline replay, uploaded-file, and Windows cleanup tests; embedded timeline fixtures support deterministic contract coverage.

## Known limitations

- ZIP catalogs and full-report serialization still materialize in memory (#161). Disk spooling and inline windows do **not** guarantee bounded-memory behavior.
- Broad test-result/attachment-volume recovery repairs remain deferred (#161); this release does not claim full collector-design compliance.
- Binary evidence paths are server-local. Remote binary hosting and binlog/dump analysis remain outside scope (#161).
- Catalog coverage does not imply unselected byte coverage. Offline replay can only return captured evidence, and incomplete prefixes/checkpoints are not snapshot blobs (#161).
