# v0.10.2 — Deterministic offline evidence workflows

Patch release completing the snapshot-backed evidence workflow and hardening Helix filtering, startup cache maintenance, and SQLite artifact handling.

## Highlights

- **Primary Helix job filtering** (#137) — `azdo_helix_jobs` now applies documented running, incomplete, failed, and issues filters to source-based Helix results using queue-monitor failure evidence, without per-job requests.
- **Snapshot-backed evidence planning** (#138) — Documentation and integration coverage now connect snapshot export, validation, and `HLX_EVAL_SNAPSHOT` replay with deterministic `azdo_evidence_plan` workflows.
- **Deterministic startup maintenance** (#139) — SQLite cache startup eviction is tracked, uses a cache-open cutoff, and is canceled and joined during disposal.
- **SQLite and artifact isolation** (#140) — Store disposal clears only its own connection pool, snapshot reads permit concurrent deletion, and existing artifacts are replaced atomically.

## New Features

- **Offline evidence workflow coverage** (#138) — Added end-to-end snapshot-backed evidence-plan coverage for complete automatic mapping, deterministic ambiguity, and missing-cache failure without network fallback, alongside expanded snapshot export, validation, replay, and authentication-partition documentation.

## Bug Fixes

- **Primary filtering correctness** (#137) — Bound parsed queue-monitor failures to matching primary Helix jobs so failure and state filters return the intended rows. Unavailable timeline evidence now produces an explicit inconclusive result for failure-based filters.
- **Startup cache lifecycle** (#139) — Replaced fire-and-forget startup eviction with tracked maintenance pinned to the cache-open timestamp, preventing delayed startup work from deleting entries written after construction.
- **SQLite pool isolation** (#140) — Disposing one cache store no longer clears unrelated SQLite connection-string pools.
- **Windows-safe snapshot artifacts** (#140) — Snapshot export permits concurrent artifact eviction, and cache updates atomically replace existing artifacts while surfacing publication failures before metadata is updated.

## Dependencies

- No dependency changes.

## Infrastructure

- Added deterministic snapshot/evidence integration coverage and cross-platform SQLite concurrency regressions, including Windows-specific sharing behavior (#138, #140).
