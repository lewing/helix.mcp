# v0.10.1 — Reliable active queue-monitor discovery

Patch release ensuring active queue-monitor evidence and metadata remain available when Azure DevOps omits the GitHub repository name required for source-based Helix job discovery.

## Highlights

- **Active queue-monitor evidence** (#132) — `azdo_helix_jobs` exposes errors and warnings from running timeline tasks through build-level `timelineIssues`, before the monitor finishes.
- **Queue and retry metadata** (#132) — Job results retain queue, state, work-item count, retry lineage, task error/warning counts, and bounded messages for investigation while a build is active.
- **GitHub repository ID source fallback** (#135) — GitHub-backed builds with a blank repository name now use the repository ID, such as `dotnet/runtime`, when computing the Helix source.

## New Features

- **Active queue-monitor diagnostics** (#132) — Primary Helix discovery is enriched with timeline issues independently of final job outcomes, preserving active errors and warnings without requiring timeline fallback.

## Bug Fixes

- **Source-based Helix discovery** (#135) — Fixed sources such as `pr/public//refs/pull/.../merge` by falling back to a nonblank GitHub repository ID when the repository name is missing. Non-GitHub and unknown repository types keep the existing behavior so opaque Azure DevOps repository IDs are not used as Helix source names.
