# v0.13.1 — Stored-credential auth for stdio MCP

Patch release fixing Helix authentication for the stdio MCP server. `hlx mcp` previously ignored the token saved by `hlx login` and only honored the `HELIX_ACCESS_TOKEN` environment variable, so `helix_auth_status` reported anonymous even after a successful login. It now resolves the same env var → stored credential chain as the CLI, falls back to the macOS Keychain when `git credential` cannot reach it, and keeps token-authenticated cache data out of the shared public cache.

## Highlights

- **`hlx mcp` uses your `hlx login` token** (#176) — the stdio MCP server now resolves `HELIX_ACCESS_TOKEN` → stored credential, exactly like the CLI; `helix_auth_status` reports the stored credential. Restart your MCP server after running `hlx login`.
- **macOS Keychain fallback** (#176) — when `git credential fill` can't reach the Keychain (for example inside apps that ship their own git without a `credential.helper`), the token is read directly from the Keychain.
- **Per-token cache isolation** (#176) — CLI and stdio MCP now partition the cache root by the resolved Helix token. Token users get a fresh `cache-<hash>` cache directory once; existing `public` entries are not reused.
- **Safer `hlx logout`** (#176) — logout now verifies the token is actually gone from the Keychain and reports a failure with removal guidance instead of claiming success.

## Bug Fixes

- `hlx mcp` (stdio): registers the chained env var → stored-credential token accessor instead of the env-var-only accessor, so tokens stored by `hlx login` are used (#176). The HTTP MCP server's header-based auth is unchanged and never reads the host keychain.
- Credential lookup: on macOS, falls back to a read-only `/usr/bin/security find-internet-password` lookup (HTTPS items only, no shell, short timeout) when `git credential fill` returns nothing or fails (#176).
- Credential lookup: `git credential fill` now runs with `GIT_TERMINAL_PROMPT=0` and `GCM_INTERACTIVE=never` so lookups never block on an interactive prompt (#176).
- Token resolution: a credential-store failure (e.g. git not on `PATH`) now degrades to unauthenticated instead of throwing (#176).
- `hlx logout`: if the token is still present in the macOS Keychain after `git credential reject`, prints a warning with a `security delete-internet-password` command and exits with code 1 (#176).
- Cache: CLI and stdio MCP cache roots are partitioned by the resolved Helix token (`{base}/cache-<hash>`); unauthenticated use stays on `{base}/public`, so private job data is no longer written to the shared public cache. `hlx cache status` labels the context accordingly (#176).
- Credential helper processes are killed when the caller cancels, not only on timeout (#176).
