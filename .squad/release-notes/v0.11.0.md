# v0.11.0 — Deterministic offline CI evidence and machine-readable errors

## Headline

A minor release that makes AzDO/Helix CI evidence deterministic and replayable offline — `hlx collect azdo-build` captures a credential-free snapshot, `hlx mcp` can replay it with no AzDO/Azure credentials, and every CLI/MCP failure now carries a stable, machine-readable `{ kind, provider, ... }` error instead of an ambiguous empty result.

## Highlights

- **Collect → snapshot → credential-free MCP replay** (#153, #155, #156, #157) — `hlx collect azdo-build <build>` gathers AzDO + Helix evidence into a versioned, exportable snapshot; `HLX_EVAL_SNAPSHOT=<snap> hlx mcp` replays it anywhere with no `AZDO_TOKEN` or `az login`.
- **Machine-readable acquisition errors** (#153) — CLI acquisition failures emit `{ ok: false, error: { kind, provider, operation, resource, ... } }`; MCP acquisition failures set `isError: true` and expose `{ error: { kind, provider, operation, resource, ... } }` in `structuredContent`. Both use stable `kind` values (`not_found`, `access_denied`, `rate_limited`, `timeout`, `transport_error`, `invalid_response`, `not_in_snapshot`), so callers can script retry/skip/fail decisions instead of guessing from prose.
- **Helix-aware evidence plans** (#153, closes #152) — `azdo_evidence_plan` parses arcade queue-monitor timeline issues into structured `helixFailures[]` with `suggestedFetches[]`, and any partial Helix-failure page now fails closed (`complete=false`, exit `2`) instead of silently under-reporting failures. Requested by Vitek Karas.
- **Paginated, envelope-shaped AzDO list output (BREAKING)** (#154) — `azdo changes`, `azdo test-runs`, `azdo test-results`, `azdo artifacts`, and `azdo test-attachments` now emit `{ ok, results, returned, total, offset, limit, complete, truncated, next, cache, note }`; truncated pages exit `2` unless `--allow-truncated` is passed.
- **`hlx collect azdo-build`** (#155, #156, #157) — one-command deterministic evidence collection with resumable manifests, byte-budgeted optional Helix file downloads, bounded all-outcome test collection, and post-export snapshot validation.
- **Critical data-loss fix** (#156) — SQLite metadata could silently store NUL-containing cached values (notably large raw AzDO logs) as zero bytes. Reported by PureWeen — see **Data loss fix** below.

## Breaking changes

- **AzDO list commands now return a JSON envelope, not a bare array.** `hlx azdo changes`, `azdo test-runs`, `azdo test-results`, `azdo artifacts`, and `azdo test-attachments` (#154) emit `{ ok, results, returned, total, offset, limit, complete, truncated, next, cache, note }`. Migration: read rows from `.results[]`; the old bare-array length is now `.returned`, and the full selected-list count is `.total`.
- **Truncated list pages fail closed.** Bounded list output exits `2` when `truncated == true` unless `--allow-truncated` is supplied (#154). Migration: fetch `.next`, rerun with `--all`, or pass `--allow-truncated` if a partial page is intentionally acceptable.
- **Partial evidence-plan pages fail closed.** Any partial Helix-failure page from `azdo_evidence_plan` (`helixFailureTotal > helixFailures.length`) now reports `complete=false`, `truncated=true`, `helix_failures_truncated`, and CLI exit `2` (#153). Fetch/merge remaining pages or request a limit ≥ `helixFailureTotal`.
- **CLI acquisition failures now emit a structured error envelope and exit 1.** Hard failures are `{ "ok": false, "error": { "kind": ..., "provider": ..., ... } }` from a central CLI filter instead of ad hoc stderr text or silent empty success (#153).
- **Collect manifest default path moved.** `hlx collect azdo-build` without `--manifest` now writes `hlx-collect-manifest.json` inside the effective cache directory, not the current working directory (#156, #157). Pass `--manifest <path>` for an explicit location.

## Data loss fix

**v0.10.3 and earlier could silently store cached values containing NUL bytes as zero bytes.** The main known impact is raw AzDO build logs around 6 KB and larger, which are cached with a NUL-prefixed `\0raw\n` marker — live calls usually hid this by refetching, but offline/eval snapshots could replay **empty logs while still validating as complete**. Reported by PureWeen.

Metadata values containing NULs are now encoded losslessly before storage and decoded on read; empty raw-log rows are treated as corrupt (`cache/invalid_response` in eval/offline mode, refetched live), and `hlx snapshot validate` flags empty/corrupt raw AzDO log metadata rows.

**Action required:** run `hlx cache clear` and re-collect or re-validate any snapshots produced by v0.10.3 or earlier.

## New Features

- **`hlx collect azdo-build`** (#155, #156, #157) — one-command deterministic AzDO/Helix evidence collection with resumable, versioned manifests (attempts, skips, recorded failures, retry outcomes, auth/replay metadata), `--download-helix-files` with streaming byte-budget caps, bounded `--test-scope all` collection, and `--export` to a replayable snapshot.
- **Credential-free snapshot replay** (#155, #156) — exported manifests record the non-secret AzDO cache partition (`auth.azdo.cachePartition`); `hlx mcp` with `HLX_EVAL_SNAPSHOT` reuses it automatically with no `AZDO_TOKEN`/`az login`.
- **Helix-aware `azdo_evidence_plan`** (#153, closes #152) — parses arcade queue-monitor timeline issues into `helixFailures[]` (job id/name, work item, state, exit code, `suggestedFetches[]`), with paging (`helixFailureOffset`/`helixFailureLimit`/`helixFailureTotal`/`helixFailuresTruncated`) and stable `incompleteDetails[].code` values.
- **Structured acquisition errors everywhere** (#153) — CLI and MCP failures share one error shape (`kind`, `provider`, `operation`, `resource`, optional `httpStatus`/`retryAfterSeconds`); snapshot replay reproduces recorded deterministic failures (`not_found`, `access_denied`, `invalid_response`) offline with `source: "snapshot"`, `replayed: true`, `recordedAt`.
- **Complete-list AzDO paging** (#154) — `--all`, `--offset`, `--limit`, `--allow-truncated` on the five AzDO list commands; `--all` populates complete-list cache keys so capped MCP/list calls can replay offline from scanner snapshots.

## Bug Fixes

- **SQLite NUL data loss** (#156) — see **Data loss fix** above. Reported by PureWeen.
- **Paging correctness** (#156) — AzDO list fetches follow continuation tokens across all provider pages and fail closed on repeated tokens/URLs or more than 1000 pages.
- **Collector robustness** (#156, #157) — thread-safe manifest attempt appends; cached evidence is verified before marking resumed entries complete; selected Helix file downloads retry within byte budgets; provider `Retry-After` is honored up to a 1-hour safety ceiling (not clamped by `--retry-max-delay`); disabled caching (`HLX_CACHE_MAX_SIZE_MB=0`) is rejected; credentials/query/fragment data are redacted from recorded argv URLs.
- **Full outcome coverage for `--test-scope all`** (#156, #157) — requests every AzDO-accepted `TestOutcome` value; the previously advertised `NotRunnable` value (rejected by the AzDO API) is no longer requested.
- **TTL-independent final verification** (#156) — pre-export cache-evidence checks now ignore live-mode TTL, so expired-but-present rows are correctly treated as exportable/replayable.
- **Optional-download budget isolation** (#156) — required evidence is acquired and verified before any optional Helix file download begins, so the collector's own optional downloads can no longer evict already-collected required evidence.
- **Invalid-snapshot completeness** (#156) — post-export validation failures now set `complete=false` and exit `1` with `snapshot_validation_failed` recorded in the manifest.
- **Response-body and transport classification** (#157) — post-send body reads (`ReadAsStringAsync`/`ReadToEndAsync`) and the Helix SDK boundary now classify every failure path, including `Azure.RequestFailedException` wrapping a raw transport error; a true last-resort catch prevents an unclassified exception from crashing collection with zero manifest.
- **Bounded all-test collection** (#157) — `collect --test-scope all` refuses more than 10,000 results without an explicit sufficient `--max-test-results`; attachment coverage defaults to diagnostic outcomes with a 1,000-request cap.
- **Resume manifest tolerance** (#156) — manifests from older collectors with duplicate attempt IDs load last-wins instead of throwing.

## Security

- **URL/SAS redaction** (#153) — URL query strings and fragments are redacted from serialized error `resource` values and recorded argv URLs, preventing signed URLs or tokens from leaking into errors or manifests.
- **Isolated export cache** (#157) — `hlx collect azdo-build --export <dest>` without an explicit `--cache-dir` now collects into a fresh, isolated per-run temporary cache directory before export, so the exported snapshot contains only this run's evidence rather than the entire shared cache (other builds, other AzDO auth partitions). The isolated path is recorded at `command.options.cacheDir`. Supplying an explicit `--cache-dir` (or standalone `hlx snapshot export`) still exports that whole cache directory — pass an isolated `--cache-dir` yourself for the same containment there.

## Infrastructure

- **Collect manifest default path** (#156, #157) — `hlx collect azdo-build` without `--manifest` writes `hlx-collect-manifest.json` inside the effective cache directory rather than the current working directory, so local auth-partition hashes and absolute cache paths stop landing in the repo by accident.
